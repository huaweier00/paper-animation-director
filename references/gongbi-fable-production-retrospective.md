## 适用范围

制作柔和工笔、绢本设色、壁画转译、历史寓言、神话或文化故事时阅读本文件。它补充通用的空间与分层规则，重点防止以下问题：

- 把“纸片动画”误做成厚纸、纸浆、白边或浮雕；
- 角色一致，但镜头中的弓箭、植物、黄金、榜文等物件不可信；
- 台词提到关键物，画面却没有出现或出现了错误替代物；
- 人物、车马或队伍不在同一地面上；
- 画面暗示了命令，却漏掉声音或结果状态；
- 片尾只交代出处，没有完成情绪、教育意义与文化升华；
- 背景音乐版本意外丢失旁白；
- 社交平台文件过大，压缩时又破坏工笔线条。

## 项目结果

《九色鹿》项目以敦煌莫高窟第257窟《鹿王本生图》为主要视觉与叙事依据，以《佛说九色鹿经》为补充文本依据。项目选择抖音横屏 16:9、1920×1080、30 fps，不制作竖屏衍生版。

视觉表面最终锁定为：

```text
柔和手绘工笔设色
+ 细线描
+ 绢本般平滑底
+ 矿物色薄染
+ 克制景深与分层运动
- 厚重纸纤维
- 白色裁切边
- 浮雕纸层
- 卷边
- 纸浆颗粒
```

最终 V2 成片为 138.233 秒，H.264 High、yuv420p、BT.709、AAC 48 kHz 双声道，综合响度约 −14 LUFS。水印版相对无水印混音母版的 VMAF 为 95.97。旁白恢复版后续压缩为约 77.2 MB，相比约 140.5 MB 的源文件减少约 45.1%，VMAF 为 95.71；画幅、帧率、时长和音频内容保持不变。

这些数字不是所有项目的固定目标，但说明一条可复用原则：先保留高质量母版，再制作经过完整解码、抽帧和客观指标验证的社会化版本。

## 完整制作过程

### 1. 选题与平台合同

先确认四件事：

1. 大众是否熟悉或容易产生情绪反应；
2. 故事是否有可见冲突和教育意义；
3. 是否适合用二维分层、横卷、完整角色状态和克制运动表现；
4. 平台画幅、时长、字幕、水印和互动目标是什么。

《九色鹿》的抖音入口不是洞窟百科，而是“被救者带着军队回来抓救命恩鹿”的背叛冲突。横屏不是后期裁切决定，而是从故事动作表开始锁定的空间合同。

### 2. 史料、版权与改编边界

建立来源等级和明确的采用/排除表：

- 采用莫高窟第257窟的横卷叙事、北魏线描、车乘、山林和矿物色语言；
- 采用经文与研究说明中的故事骨架和保护结果；
- 不把文物误写为非遗；
- 不复制1981年动画版的角色造型、分镜、台词、场景或音乐；
- 不把北魏壁画世界泛化成唐风、明清宫殿或仙侠游戏。

### 3. 故事动作表与结尾合同

把故事拆成九幕，每幕都写：

```text
目标 → 起因 → 动作 → 传播 → 结果 → 静音证明
```

同时在开工前写出片尾三层收束：

1. **故事后果**：围猎停止、九色鹿得到保护、背誓者失去重赏；
2. **文化回归**：回到第257窟横卷与其由两端向中央汇合的阅读结构；
3. **可迁移道理**：守信是利益面前仍不背弃；文明是用规则让善意不再孤立无援。

互动问题可以出现在发布文案或置顶评论中，但不能替代影片内部的主题结论。

### 4. 身份参考与镜头素材分离

为九色鹿、溺水者、乌鸦、王后、国王和护卫群分别批准一张正面、中性、完整、只用于一致性条件的身份参考图。

首轮身份图因纸感过重而被整体驳回。柔和工笔版本批准后，身份图仍未直接进入任何镜头。每个镜头中的背景、姿势、接触状态、道具和效果均在镜头空间合同通过后另行生成。

### 5. Fish Audio 公开市场选角

按声部分别搜索公开市场。实际项目为每个声部保留约30个元数据候选，再选6个使用同一句文本试听，共24条试听。检查：

- 普通话与方言；
- 年龄、身份感和角色区分；
- 咬字、句尾、呼吸和情绪范围；
- 是否带营销、新闻、动漫、游戏咆哮或名人模仿倾向；
- 时长、字速、响度、响度范围和真峰值。

锁定旁白、九色鹿、溺水者和国王四组声线后，按场景或台词生成正式干声。保留公开模型 ID、市场页面、试听文件、选择理由和淘汰记录，不保存凭证。

### 6. 基准镜头

先制作第三幕“逆流救人并上岸立誓”的 8–15 秒基准：

- 鹿入水；
- 人被水流带离；
- 鹿肩颈承接重量；
- 人由乱抓转为抱住鹿颈；
- 鹿因负重下沉并逆流转向；
- 两者上岸。

救援采用镜头专用连体接触状态或完整场景多帧，不能用两个独立 PNG 靠近代替承重。

### 7. 逐镜循环生产

九个镜头严格按以下循环制作：

```text
语义合同
→ 俯视空间与正视机位
→ 镜头专用最小资产
→ 草稿动画
→ 渲染 MP4
→ 静音/只听声音/画音字幕合看
→ 现实物件与地面接触检查
→ 高质量定版
→ 放行下一个镜头
```

项目不把“已生成”视为“可使用”，不把浏览器预览视为交付证据。

### 8. 首版装配与技术交付

九镜定版后完成：

- 场景拼接与边界检查；
- 原创低存在感氛围声床；
- 旁白、对白与声床混音；
- EBU R128 响度归一化；
- 动态账号水印；
- H.264/AAC 抖音横屏交付；
- 完整解码、FFprobe、抽帧、字幕安全区和 VMAF 检查。

首版技术上合格，但用户用十张截图指出了内容与现实可信度问题。技术通过不能覆盖内容失败。

### 9. V2 逐镜返修

V2 不在最终 MP4 上遮盖补丁，而是回到受影响镜头的空间合同、源素材、动画和声音重制。九镜中除未受影响的一镜外，其余八镜重新完成草稿、抽帧和高质量定版。

新增了国王命令放下弓箭的旁白，并重写片尾，使总时长从约127.9秒增长到138.233秒。之后重新拼接、混音、水印和技术审查。

### 10. 旁白恢复

后续出现了一个时长未变、背景音乐仍在、但旁白丢失的外部版本。恢复时：

1. 不改画面和总时长；
2. 不重新选音色或重生成台词；
3. 按原声部、原台词和原时间点重新铺回已批准干声；
4. 在语音窗口对背景音乐做适度 ducking；
5. 检查全部预期台词、时长、响度和完整解码；
6. 输出新文件，不覆盖来源文件。

### 11. 社会化压缩

对旁白恢复母版制作单独的 H.264 社会化版本：

- 保持1920×1080、30 fps、BT.709；
- 音频已合适时直接复制，避免再次有损编码；
- 使用适合手绘动画和线条的编码设置；
- 完整解码；
- 对全片计算 VMAF，门槛通常为95；
- 抽查开头、中段、高潮和片尾的工笔线条、字幕和色彩；
- 报告文件大小、压缩比例、技术参数和哈希。

## 首版为什么仍然失败

| 症状 | 真正根因 | 新的拒收条件 |
| --- | --- | --- |
| 箭横跨大半画面 | 把瞄准方向线画成实体箭 | 箭尾、弓弦、弓身、箭头必须构成现实结构；长度以持弓者身体尺度校验 |
| 水草没有出现或漂到鹿头上 | 只画“被卷走”的概念，没有根点、手和岸线接触 | 同帧看见根部、叶形、抓持点；断裂发生在根部，碎草沿水流运动 |
| 红线意图不清 | 用跨场景长线代替立誓动作 | 让角色亲手系短绳、收紧、留下可辨状态；隐喻必须依附真实动作 |
| 悬赏榜像占位符 | 用图标和几条线代替官方文书 | 正式文书形制、信息层级、印记和可读关键词必须成立 |
| 黄金像土堆或不明物 | 用抽象几何符号代替材质与器物 | 使用可辨的金饼、金锭、金币或时代适配形制；厚度、边缘、高光、容器和尺度必须成立 |
| 带路人走在空中 | 人物与车队共用错误缩放/位移，脚底线未锁 | 带路人有独立路面与基线；脚、车轮、马蹄和影子在所有审查帧中接触地面 |
| 高潮箭支仍不合理 | 方向线错误被跨镜复用 | 武器素材也必须逐镜审查，不因首镜已出现而默认合格 |
| “放下弓箭”没有旁白 | 画面状态与剧本声音清单未做逐句对照 | 命令、手势、队伍响应和安全结果在同一时间窗，声音账本中有对应台词 |
| 片尾平淡 | 只完成出处说明，没有完成价值论证 | 后果、文化出处、可迁移道理三层缺一不可 |
| 技术 QA 通过却仍需大修 | QA 偏重编码、字幕和空间，没有“现实物件可辨认”门 | 每镜增加现实参照、关键名词存在性和对象类别识别检查 |

## 新增硬门槛

### 1. 表面风格合同

分别锁定：

- **动画方法**：分层、状态帧、完整角色、可控时间轴；
- **表面媒介**：工笔、绢本、水彩、壁画、剪纸或用户指定风格。

不要从“纸片动画”自动推断厚重纸纹。表面媒介写入禁止项，并在身份图、第一张镜头素材、基准镜头和最终抽帧中重复检查。

### 2. 关键物件可辨认合同

每个故事关键名词至少记录：

```yaml
id: reward-gold
class: period-appropriate-gold-object
silhouette: multiple thick round gold cakes in a dark open box
scale_reference: each piece approximately palm-sized
material_cues: warm metallic highlight, visible thickness, stamped center
support_or_attachment: resting inside a box on a platform
state_sequence: closed-box -> open-recognizable-gold -> withdrawn-from-betrayer
proof_time: 6.2
forbidden_substitutions: [soil-pile, red-cloth-mound, flat-yellow-circles, triangle-icon]
```

没有这个合同，不生成关键物件。音频关闭后，审片者应能说出它是什么，而不是“像某种符号”。

### 3. 文书与文字合同

图像模型不可靠地生成重要文字时：

1. 生成空白但形制正确的卷轴、木牍、榜文或牌面；
2. 用确定性排版加入已校对文字、官印、层级和方向；
3. 检查历史书写方向、字距、对比度和安全区；
4. 禁止用三条横线、鹿头简图或现代信息图图标替代正式文书。

### 4. 支撑面合同

每个主体声明 `support_surface`：

- 人物脚底对应道路、地板、台阶或舟面；
- 马蹄和车轮对应同一透视地面；
- 盒、榜、灯和器物有桌面、墙面、手或挂点；
- 水草有根部，绳结有腕部，箭有弓弦和弓身。

任何“看起来悬着”的主体在 P1 失败。

### 5. 命令与集体响应合同

集体状态变化至少包含：

```text
危险初态 → 发令者可见命令/手势 → 接收者依次响应 → 安全终态
```

如果声音说“放下”，最终状态必须确实比初态更低、更安全且保持足够时间供观众看清。

### 6. 逐镜放行合同

为当前镜头保存放行记录，至少包含：

- 合同版本与素材版本；
- 草稿 MP4 和定版 MP4；
- 现实参照或物件规范；
- 静音、声音、画音字幕、现实物件四次审查结论；
- first/mid/proof/final 抽帧；
- 技术检查结果；
- `approved` 或 `rejected`；
- 若拒绝，根因和下一次修订目标。

只有 `approved` 才能开始下一个镜头。批量生成后再回头审片会放大错误复用。

## 声音丢失后的恢复规则

### 声音账本

在最终混音前保存：

```yaml
timeline_duration: 138.2
lines:
  - id: scene-08-narrator-command
    speaker: narrator
    text: 国王听完真相，抬手命令所有弓手放下弓箭。
    source: assets/audio/formal/scene-08-command.wav
    start: 86.4
    measured_duration: 4.8
    gain_db: 0
    required: true
music:
  source: assets/audio/bgm.wav
  duck_under_required_lines: true
```

交付前逐条验证 `required: true` 的源文件、时间点和可听性。保留：

- 原始干声；
- 只含全部语音的 reference mix；
- 只含音乐/环境的 stem；
- 最终 full mix；
- 文件哈希与总时长。

### 恢复原则

当音乐版缺少旁白但画面时长未变：

- 先确定是不是混音或封装丢轨，不重做画面；
- 使用原始语音账本重建；
- 不以新的 TTS 代替已批准表演；
- 不压缩或拉伸台词去追逐已有画面；
- 恢复后做 voice-only、full-mix 和字幕同步检查；
- 输出带明确版本名的新文件。

## 最终交付规则

至少保留：

1. 可编辑项目；
2. 身份参考与逐镜资产；
3. 每镜合同、放行记录和抽帧；
4. 语音账本、试听、干声、voice-only mix、BGM stem、full mix；
5. 无水印高质量母版；
6. 动态水印母版；
7. 压缩社会化版本；
8. FFprobe、响度、完整解码、VMAF和哈希报告；
9. 平台标题、描述和置顶评论候选。

文件命名必须区分 `master`、`watermarked`、`voice-restored`、`social` 和版本号。不得用“最终版2”“最新版”这类无法审计的名称覆盖已有文件。

## 逐镜放行清单

在开始下一个镜头前逐项回答：

- [ ] 当前镜头的关键名词都真实出现了吗？
- [ ] 物件类别、比例、材料和用途一眼可辨吗？
- [ ] 箭、绳、植物、器物、文书等有真实连接点或支撑点吗？
- [ ] 人脚、动物蹄、车轮和放置物都接触同一可信地面或承载面吗？
- [ ] 角色方向、视线、路径和前后关系符合旁白吗？
- [ ] 指令是否具有初态、命令、响应和终态？
- [ ] 身份参考只作条件，没有直接进入镜头吗？
- [ ] 工笔线条完整，表面没有违背用户要求的厚纸感吗？
- [ ] 静音能否看懂起因、动作和结果？
- [ ] 只听声音能否确认每句的说话者、口音、情绪和时间？
- [ ] 画音字幕合看是否在同一语义节拍？
- [ ] first/mid/contact/proof/final 抽帧是否来自真实渲染 MP4？
- [ ] 是否记录 `approved`，并保留本镜的定版文件？

任一项为否，当前镜头不放行。
