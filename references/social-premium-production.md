## 目标

把“制作正确”升级为“值得停留、看完、记住和收藏”。传播不是成片后的包装步骤，而是故事、镜头、声音和结尾在开工前共同承担的职责。

对抖音精品叙事动画，按以下顺序判断成功：

```text
停留意愿 → 故事理解 → 情绪/认知回报 → 收藏对象 → 制作可信度 → 技术交付
```

不得用技术合格替代传播成立，也不得用强钩子替代完整论证。精品是每一层都通过，不是靠更长工期、更高分辨率或更多引擎堆出来。

## 适用原则

1. 当目的地是抖音或同类竖屏信息流时，默认从 `9:16`、`1080×1920` 的原生构图开始。横屏并非禁止，但必须记录不可替代的叙事理由，并通过真实竖屏 Feed 预览证明人物、字幕、动作和关键物仍然可读。
2. 不在故事开头播放 Logo、片名、系列名、空山水或来源说明。先完成承诺，再展示身份。
3. 不为追求“快节奏”机械规定镜头长度。长镜头、静止和留白必须承担悬念、观察、情绪、信息或审美职责，并在粗剪中证明观众仍有理由停留。
4. 不把“每 1.5–3 秒出现新视觉信息”理解为乱切镜头。新信息可以是动作阶段、视线变化、物件状态、空间揭示、光色转折、声音事件或构图关系变化。
5. 不以赶进度为放行理由。对 `quality_posture: premium-quality-first` 的项目，只依据门禁证据批准；脚本、粗剪、配音、资产和镜头均允许回退重做。
6. 不伪造冲突、来源或历史事实。钩子可以先给后果、疑问或反常识判断，但必须由本片内容兑现。

## 《守株待兔》传播复盘

本门禁来自一支已完成工笔纸片动画的真实失败模式。该片在空间、人物、字幕、音频和编码层面可以交付，但传播结构仍然普通：

- 成片 50.4 秒、1920×1080 横屏；
- 前 8.8 秒主要介绍农夫耕田和树桩；
- 兔子约 9.4 秒才进入，约 10.9 秒才撞树；
- 全片主要依靠 7 个大场景、完整人物贴图、缓慢推拉和轻微浮动；
- 旁白按已知情节顺序复述，结尾道理正确但泛化；
- 横屏 36px 字幕缩进竖屏 Feed 后过小；
- 声音技术电平正常，但关键叙事音效集中在兔子掠过和撞击，人物“放下锄头”的选择没有声音重音；
- 封面以系列名“寓言千年”为主，单集冲突和收藏回报不明确。

这证明：P0–P3 通过只能说明影片可信、可读、可交付，不能说明用户愿意停留或收藏。可迁移规则是：

1. 把最强可见事件或其后果放入首三秒；
2. 对观众熟悉的故事，用新解释代替情节悬念；
3. 先在粗剪中证明选择、代价和结尾回报，再精修工笔资产；
4. 为角色决定设计动作和声音，不只为事故设计动效；
5. 系列名作角标，单集冲突作封面主标题；
6. 给结尾一个观众以后能使用的对象，而不只是一句正确道理。

## S0 传播合同

在正式剧本、正式配音和任何镜头素材生成前，向 `story-manifest.json` 写入 `platform` 与 `social_contract`。

至少锁定：

- `destination`：发布目的地；
- `distribution_mode`：信息流原生、横屏长视频或其他；
- `primary_audience`：只写一类核心观众，其他人是次级观众；
- `quality_posture`：精品质量优先；
- `aspect_decision`：画幅、理由、Feed 预览要求；
- `editorial_promise`：观众看完会得到什么；
- `familiarity_gap`：如果故事很熟，本片提供什么新解释；
- `opening`：首帧事件、首句、三秒内兑现的视觉证据；
- `value`：可迁移洞见、现代连接和收藏对象；
- `packaging`：系列角标、单集冲突标题、封面主体与发布提问；
- `animatic`：首三秒样片与全片粗剪的文件和审批状态。

一个合格承诺必须具体，例如：

```text
不合格：讲清《守株待兔》的道理。
合格：用《守株待兔》解释“为什么一次偶然的成功会伤害判断力”，并留下三问复盘卡。
```

一个合格的 `save_object` 必须是观众以后愿意再看的对象，例如：

- 三问或三步判断卡；
- 一句经过剧情证明的可引用结论；
- 可复用的辨别框架；
- 有来源价值的服饰、器物、时代或工艺图谱；
- 可用于亲子讨论的具体问题卡。

“请收藏”“寓言千年”“完”不是收藏对象。

## S1 首三秒样片

故事合同通过后，先做一个独立的 0–3 秒样片。它可以使用线框、色块、低清分镜、临时音效和临时旁白；不得为了这个门禁提前生产可交付角色资产。

首三秒样片必须回答：

1. 第一帧是否已经存在事件、异常、选择、结果或强视觉关系？
2. 第一句是否制造具体问题，而不是报幕或百科说明？
3. 三秒内是否出现能够兑现这句承诺的视觉证据？
4. 静音时是否仍能看出“值得继续看”的变化？
5. 声音是否在首帧就建立方向、冲击或情绪，而不是等画面说明完才进入？
6. 封面承诺与首帧是否属于同一个故事，不形成点击后的落差？

以下开头默认拒收：

- Logo、系列名、片名先行；
- 空景慢推、卷轴慢开、墨迹慢显；
- “很久很久以前”“宋国有个农夫”式无冲突介绍；
- 只有抽象金句，没有对应人物、物件或后果；
- 依靠整屏大字掩盖画面没有事件；
- 三秒内承诺了本片不会证明的夸张结论。

样片只在 `hook_review: approved` 后放行全片粗剪。失败时回到故事和开头，不生成正式资产补救。

## S2 全片低成本粗剪

在正式选角、最终语音和逐镜精品资产之前，制作完整 scratch animatic。使用：

- 分镜图、色块、轮廓、现有参考图的不可交付低清替身；
- 临时旁白或导演读稿；
- 临时字幕；
- 关键音效占位；
- 明确的视觉节拍标记。

粗剪必须证明：

- 开头承诺在正文中被兑现；
- 每一段都推进了冲突、选择、后果、情绪或认知；
- 熟悉故事没有被逐句复述；
- 旁白没有重复画面已经清楚展示的事实；
- 冲突或核心问题不会晚到足以让前段变成说明书；
- 结尾不是泛泛说教，而是剧情挣得的结论；
- 收藏对象有足够可读时间，并且确实比一句“记得收藏”更有用；
- 删除任一镜头时，能说明损失了什么；说不出就删除或合并；
- 故意的静止、空白或长镜头有书面职责和声音/表演支撑。

给每个生产镜头声明 `visual_beats`：

```json
[
  {"time": 0.0, "change": "兔子冲入前景草丛", "function": "hook"},
  {"time": 1.1, "change": "兔子撞树，农夫猛然回头", "function": "impact"},
  {"time": 2.4, "change": "撞击停格并显出代价问题", "function": "promise-proof"}
]
```

`visual_beats` 记录观众获得的新信息，不是装饰层清单。超过默认视觉节拍间隔的段落，需要 `long_hold_rationale` 说明持续观察的价值，并在粗剪中单独批准。

只有 `full_edit_review: approved` 才进入正式声音和镜头生产。粗剪失败时允许任意次数重写；不要因已经画过分镜而迁就。

## S3 精品生产与社交交付

粗剪通过后，恢复本 Skill 的正式生产纪律：最终语音、身份锁定、镜头空间合同、高风险基准镜头、逐镜资产、动画、放行和交付。

精品模式额外要求：

- 一次只精修一个镜头，当前镜头未批准不开始下一个；
- 角色、道具和声音的错误回到源头修，不在总成片上遮补丁；
- 开头、核心选择、后果和结尾收藏对象是四个必须单独审查的 editorial proof；
- 画面运动围绕人物选择与物件状态，不用缓慢推拉冒充事件；
- 声音至少覆盖开头方向、关键接触、角色选择、时间/后果转折和结尾行动；
- 完片后制作竖屏 Feed 模拟预览，叠加右侧按钮区、底部文案区和设备边界，检查标题、脸、手、字幕和收藏卡；
- 封面在主页缩略图尺寸和 Feed 尺寸分别检查；系列名只作角标，单集冲突是主标题；
- 母版、平台上传版、封面和发布文案分开保存。

## 熟悉故事的新解释

观众已经知道结局的寓言、神话和成语，不以“后来发生什么”作为唯一悬念。先写 `familiarity_gap`：

```text
观众已经知道：农夫等不到第二只兔子。
观众未必想过：真正的危险不是懒，而是把偶然成功误认成可复制能力。
```

优先从以下角度寻找新解释：

- 角色作出错误决定前，哪一个念头最诱人；
- 代价不是“受罚”，而是什么能力、关系或时间被慢慢损耗；
- 故事中的机制如何迁移到创作、工作、投资、教育或关系；
- 原典与大众简化版本之间有什么值得纠正的差异；
- 角色是否仍有修正可能，避免单纯嘲笑愚蠢。

新解释必须由剧情、动作或关键物证明。不能在结尾突然塞入与前片无关的现代金句。

## 旁白、画面与声音

### 旁白

- 首句承担问题、反差、代价或选择，不承担时代报幕；
- 把可见动作交给画面，把角色误判、隐含因果和现代迁移交给旁白；
- 优先使用可说、短、具体、有动词的句子；
- 一句只承担一个主要转折；
- 结尾句应可记忆，但必须由前面的故事证明；
- 不用全局加速配音弥补剧本冗长，先删改文字；
- 正式音色在完整粗剪通过后锁定，避免用昂贵表演绑定错误结构。

### 画面

- 第一帧、关键选择、后果和重新行动优先使用动作或接触，而不是解释字幕；
- 用景别、视线、姿势、道具状态、光色和空间变化提供视觉节拍；
- 同一全身人物在同一构图中停留过久时，主动寻找手、眼、脚、关键物或环境反应的近景；
- 保留纸片动画的克制与留白，但确保留白之后有明确回报；
- 角色表演与物件接触优先于背景细节和装饰纹理。

### 声音

- 让首帧就有听觉方向；
- 为关键选择设计声音，例如锄头落地、门闩合上、绳结收紧；
- 用声音显示时间和环境状态变化，不让一条氛围床从头铺到尾；
- 在后果揭示前允许主动抽掉音乐，制造可感知的空；
- 技术响度合格不等于声音叙事合格。

## 封面、首帧与收藏对象

封面负责“为什么点开”，首帧负责“点开后为什么不划走”，结尾负责“为什么值得留下”。三者必须来自同一个承诺，但不能做成同一张静态海报。

封面合同至少声明：

- `episode_title`：单集冲突、代价或反常识；
- `series_label`：小角标，不抢主标题；
- `cover_subjects`：能一眼读懂冲突的角色与关键物；
- `cover_copy`：短、具体，不只写成语名；
- `feed_to_opening_match`：封面与首帧的兑现关系；
- `thumbnail_review`：主页缩略尺寸审查状态。

结尾收藏对象要在字幕安全区和真实设备预览中检查。信息卡的字号、行数、停留时间和旁白不应互相争夺阅读。若观众需要暂停才能读完，延长停留、减少文字或拆成两步；不要靠提高语速解决。

## 复盘规则

发布后只用该账号自己的数据做相对比较，不把外部“万能完播率”写进 Skill：

- 首屏/早期流失主要回看封面、首帧、第一句和承诺兑现；
- 中段流失回看重复解释、无状态变化和冲突来得过晚；
- 看完但少收藏，回看洞见是否太泛、收藏对象是否无用或不可读；
- 收藏但少评论，回看发布问题是否过于抽象；
- 视觉评价好但播放弱，优先修编辑结构，不继续堆美术细节。

每次复盘只改一个主要变量并保留版本：封面、首句、前 3 秒、片长、结尾卡或发布问题。把真实结果写入项目复盘；出现两次以上的同类失败，再升级为 Skill 规则或审计字段。
